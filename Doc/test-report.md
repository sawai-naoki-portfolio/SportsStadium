# テスト仕様・結果 — スポーツスタジアム

## 1. 方針

| 種類 | ねらい |
|---|---|
| EditMode テスト | 得点ルール・審判・シュートの成功率・放物線の計算・「成功判定のシュートが物理的にも入るか」・入力状態など、**ルールと計算**を検証する |
| PlayMode テスト | 各シーンを実際に起動し、画面遷移・自動対戦で得点が進むこと・タッチ操作が効くことを確認する。`FullMatchTests` は 3 種目を（難易度を変えて）**最後まで戦わせ、リザルト画面に到達する**ことを確認する。エラーログが出たら失敗 |
| 自動対戦 | `DebugOptions.AutoPlay` でプレイヤー側も CPU にし、バランス調整と動作確認に使う（戦績には記録しない） |

## 2. 実行方法

Unity の **Window > General > Test Runner** で EditMode / PlayMode を実行します。

GitHub Actions（`.github/workflows/core.yml`）では、Unity 非依存の `TennisScoreTests` だけを .NET 8 で実行します（`Tools/CoreTests/CoreTests.csproj` が `TennisScore.cs` とテストをリンク参照）。Unity のライセンスが必要な EditMode / PlayMode のその他のテストは CI では実行しません。
